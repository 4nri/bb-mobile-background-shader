# GPU Shader Handoff — мобильный фон

## Быстрый старт

```bash
git clone https://github.com/4nri/bb-mobile-background-shader.git
cd bb-mobile-background-shader
open index.html
```

`index.html` — визуальный эталон. Готовая RGB mask texture уже лежит в `assets/background_masks_rgb_135x240.png`, ничего декодировать не нужно.

Текстура 135×240 намеренно небольшая: фоновые маски очень низкочастотные и сильно размытые. Если понадобится более крупная версия, её можно пересобрать из `background_source.svg` по той же RGB-упаковке каналов.

## Рекомендуемая архитектура для продакшена

Не нужно переносить браузерный прототип в приложение как 1440 SVG-элементов с JavaScript-анимацией.

Для продакшена лучше использовать **один полноэкранный fragment shader** и **одну небольшую RGB-текстуру**:

- `assets/background_masks_rgb_135x240.png`
  - R = размытое пятно фона A
  - G = размытое пятно фона B
  - B = размытое пятно фона C
- точки генерируются процедурно прямо в шейдере
- вертикальная маска прозрачности точек считается математически
- Turbulent Displace считается процедурно через fractal noise небольшой сложности
- dither тоже генерируется процедурно

Так мы сохраняем тот же визуальный результат, но сильно уменьшаем нагрузку на CPU и вообще не используем видео.

## Утверждённые визуальные параметры

Рабочая дизайн-система координат: **2160 × 3840**.

Полный общий цикл анимации: **24 секунды**.

Почему именно 24 секунды:

- фон: `Speed = 2` → цикл фона = 6 секунд
- точки: `TD Speed = 0.25` → цикл Turbulent Displace = 24 секунды
- значит вся композиция возвращается в абсолютно исходное состояние через 24 секунды

В продакшене лучше использовать одно общее нормализованное время:

```text
master = fract(time / 24s)
bgPhase = master * 2π * 4
tdPhase = master * 2π
```

Так весь фон математически зациклен без шва.

### Текущие утверждённые значения

```text
Background Speed       2
Background Distortion  2
Dither                  10  (значение из прототипа; в native shader лучше подогнать визуально)
Brightness              1
Dots Opacity            0.2
TD Amount               20
TD Size                 6
TD Stretch              4
TD Speed                0.25
```

В самом приложении эти параметры не обязательно делать пользовательскими настройками. Это арт-дирекшн-параметры, которые можно зафиксировать константами. Выносить их в конфиг имеет смысл только если позже потребуется удалённая настройка.

## Фон

Базовый цвет: `#141514`

Цвет пятен: `#2D302F`

Три исходных SVG-пятна заранее отрендерены в виде размытых grayscale-масок и упакованы в одну RGB-текстуру. Это позволяет не считать Gaussian Blur и не рендерить SVG-path в рантайме.

Pivot для каждого канала в координатах 2160×3840:

```text
R: 1442.2636, 1232.4895
G:  962.2995,  647.3960
B: 1143.5431, 2594.9563
```

В шейдере координаты семплирования для каждого канала трансформируются через те же sinusoidal translate / scale / rotation, что используются в браузерном прототипе.

## Точки

Исходная геометрия:

```text
область: 2160 × 1512
привязана к нижнему краю артборда 2160 × 3840
Y offset: 2328
45 колонок × 32 ряда
шаг: 48 px
радиус: 9 px
цвет точек: белый
базовая opacity группы: 15%
вертикальная luminance mask: 0 сверху -> 1 снизу
```

При утверждённом `Dots Opacity = 0.2` максимальная альфа в нижней части получается:

```text
0.15 × 0.2 = 0.03
```

Это значение до antialiasing.

Точки **не должны вращаться по отдельности**.

Шейдер может:

- плавно смещать центры точек через turbulence field
- увеличивать и уменьшать точки
- слегка растягивать их по X/Y

Per-dot rotation не нужен.

## Защита краёв кадра

В пределах примерно **180 дизайн-пикселей** от физических границ экрана воздействие на точки должно плавно сходить к нулю:

- position displacement → 0
- scale bulge → 1
- stretch → 1

Это нужно, чтобы точки не выглядели так, будто их затягивает внутрь кадра снаружи.

## Turbulent Displace

Используется упрощённая мобильная версия логики, визуально близкая к Turbulent Displace:

- fractal/value noise небольшой сложности
- 2 octave для этого визуала достаточно
- отдельные decorrelated noise samples для X, Y и scale/stretch
- `TD Size` управляет пространственной частотой noise
- `TD Amount` управляет амплитудой смещения
- `TD Stretch` управляет только локальным scale/stretch
- `TD Speed` задаётся через фазу master TD cycle

В reference shader намеренно используется только 2 octave: для этого визуала большего количества деталей не требуется, а GPU-нагрузка остаётся ниже.

## Размеры экранов и разные aspect ratio

Всю математику лучше оставить в фиксированной дизайн-системе **2160×3840**.

Реальный viewport устройства нужно маппить в эту систему координат через **center crop / aspect-fill**.

Не нужно отдельно масштабировать расстояние между точками по X и Y. Иначе на экранах не 9:16 точки и расстояния между ними начнут деформироваться.

## iOS

Предпочтительный вариант для iOS 17+:

- Metal shader через SwiftUI `Shader`
- в зависимости от структуры экрана можно использовать `layerEffect` или `distortionEffect`

Если фон рендерится как отдельная полноэкранная поверхность, можно использовать обычный Metal fragment shader через `MTKView`.

На каждом кадре в shader uniforms нужно передавать совсем немного данных: время, resolution и, при необходимости, зафиксированные параметры пресета.

## Android

Для Android 13+:

- подходит AGSL `RuntimeShader`

Для Android ниже 13:

- использовать ту же математику в OpenGL ES fragment shader или в уже существующем GPU-рендерере приложения
- не делать fallback в виде 1440 анимированных View/SVG-элементов

## Требования к производительности

Желательная архитектура:

- один fullscreen draw call
- одна небольшая texture resource
- без video decoder
- без обновления каждой точки на CPU
- без runtime Gaussian Blur
- без 1440 UI-объектов

Проверять производительность нужно не только на флагманах, но и на устройствах среднего класса.

Рекомендуемые критерии приёмки:

```text
цель: 60 fps на обычных устройствах
на CPU нет постоянной анимационной работы кроме обновления времени
нет видимого шва при переходе t = 24s -> 0s
нет затягивания точек с краёв кадра
нет индивидуального вращения точек
визуальное совпадение с prototype на t = 0, 6, 12, 18, 24s
```

## Файлы в репозитории

- `index.html` — утверждённый браузерный референс
- `background_source.svg` — исходный вектор фона
- `dots_reference.svg` — исходный слой точек с маской
- `assets/background_masks_rgb_135x240.png` — упакованная RGB mask texture для продакшена
- `reference_shader.glsl` — платформонезависимый GLSL-like reference shader
- `preset.json` — параметры в machine-readable виде

`reference_shader.glsl` не нужно воспринимать как готовый copy/paste production code. У Metal и AGSL разный синтаксис и разные texture API. Главное — сохранить математику, константы, дизайн-систему координат и тайминг общего лупа.
